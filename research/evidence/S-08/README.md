# S-08 — сырые протоколы прогонов `tools/static/find_constants.py`

Каталог хранит неотредактированный вывод инструмента. Ничего здесь не правилось
руками: каждый файл — целиком вывод одного прогона.

`build_key = sha256:0eef3715244b467c830022c4260a0e2c29c7def1429cb34aa37fdf9b7e14a383`
— это sha256 файла `MISERY\Binaries\Win64\MISERY-Win64-Shipping.exe`
(134 658 048 байт), к которому относятся все файлы, кроме контрольного.

## Что этот инструмент вообще делает, и почему это два измерения, а не одно

`find_constants.py` не несёт списка константы. Каждый образец **выводится из
first-party дерева UE 5.4.4** во время прогона и несёт файл и строку, из которых
он взят. Поэтому документ разделён на две части, и путать их нельзя:

* `catalogue` — утверждение об **исходном дереве** (оракулы `external-doc` за то,
  что говорит код, и `filesystem` за то, что файл по этому пути содержит именно
  такой текст). Дерево — `D:\Program Files\UE_5.4\Engine`,
  `Build/Build.version` объявляет CL 35576357, ветку `++UE5+Release-5.4`;
* `occurrences` — утверждение об **образе** (оракул `binary-analysis`): нашлась
  ли ровно эта последовательность байт, сколько раз и по каким смещениям.

Совпадение первой части со второй — это third act, `engine_version_crosscheck`,
и он **по полям** говорит, что является новым измерением, а что — повторным
чтением уже прочитанного диапазона.

| Файл | Что это |
|---|---|
| `shipping-run1.log` | основная цель, прогон 1: полный обход дерева исходников (90 482 файла, 894,5 МБ, 441 с) |
| `shipping-run2.log` | та же цель, прогон 2, с `--catalogue-in` — дерево не обходилось заново |
| `shipping-constants.json` | полный машинный документ прогона 1: каталог, поверхность, все 205 образцов, 9 буквальных чтений класса P, пять проб на опровержение |
| `constants.jsonl` | артефакт задачи: по одной строке на ОБРАЗЕЦ (не на константу) — у таблиц и у GUID-ов образцов больше одного на константу |
| `catalogue-ue544-cl35576357.json` | сам каталог, отдельным файлом: 21 скалярная/табличная запись с цитатами вида `путь:строка` плюс перепись 108 регистраций кастомных версий |
| `control-negative-msvcp140.json` | отрицательный контроль: `C:\Windows\System32\MSVCP140.dll`, бинарник без Unreal вообще |
| `control-negative-msvcp140.log` | протокол того же прогона |

## Отрицательный контроль — оценка ложных срабатываний по измерению, а не по утверждению

На `MSVCP140.dll` (643 512 байт, ни строки Unreal) из 205 образцов найдено **2**:
`fnv64_offset_basis` и `fnv64_prime`. Это универсальные константы FNV-1a, и
`DOES_NOT_PROVE` семейства `hash-seed` заранее говорит, что попадание в них не
выделяет вызывающую сторону движка: MSVC-ий `std::hash` использует FNV-1a.

Специфичные для Unreal семейства дали **ровно 0 из 102**: `package-file-tag` 0/2,
`container-magic` 0/2, `custom-version-guid` 0/94, `hash-table` 0/3 (плюс 0/2 по
префиксам), восьмибайтовая пара версий 0. Восемь синтетических контролей — 0.
Вердикт `engine_version_crosscheck` — честный `UNKNOWN`, а не «не совпадает».

## Что найдено в целевом образе

* **Все три таблицы `FCrc` — целиком.** `CRCTablesSB8` (8192 Б) по смещению
  125 654 384, `CRCTable_DEPRECATED` (1024 Б) по 125 662 592,
  `CRCTablesSB8_DEPRECATED` (8192 Б) по 125 663 616. Каждая — ровно один раз.
  Это самые сильные анкеры прогона: таблицу на 2048 слов нельзя ни свернуть в
  immediate, ни вывести компилятором из инициализатора, ни совпасть с ней
  случайно.
* Три таблицы лежат **одним непрерывным блоком** 125 654 384–125 671 808
  (17 408 Б, зазоры 16 и 0 байт). Порядок в образе — `CRCTablesSB8`,
  `CRCTable_DEPRECATED`, `CRCTablesSB8_DEPRECATED` — **не** порядок объявления в
  `Crc.cpp` (строки 40, 60, 208), то есть компоновщик их переставил. Утверждать
  сохранение порядка объявления нельзя; смежность утверждать можно.
* **Восьмибайтовая пара версий пакета найдена ровно один раз** на всей
  поверхности 132 461 568 байт: смещение 125 682 456, байты
  `0a020000f4030000`, то есть (522, 1012). Предсказанный соседний диапазон —
  (214, 0) — совпал 1 из 1.
* `PACKAGE_FILE_TAG` — 8 вхождений, `PACKAGE_FILE_TAG_SWAPPED` — 4,
  `FPakInfo::PakFile_Magic` — 4, `TocMagicImg` — 1.
* **61 из 94** GUID-ов кастомных версий найдены, 33 отсутствуют. Каждый
  найденный — ровно дважды.

## Проба, которая сработала как проба, а не как украшение

`table prefix against the whole table` нашла расхождение: префикс `CRCTablesSB8`
(первые 256 слов) встречается **дважды** — по 125 654 384 и по 116 368 912, — а
вся таблица один раз. Первая строка `CRCTablesSB8` есть канонический reflected
CRC-32, и по 116 368 912 в образе лежит **независимая вторая копия** этой
канонической таблицы. Проба именно для этого и написана: счётчик короткого
образца объявлен не доказательством о таблице, и запись об этом стоит в
документе, а не в примечании.

## Повторяемость

Прогон 2 (`--catalogue-in`) дал тот же блок `Occurrences, by family` и то же
единственное совпадение пары версий. Девять чтений класса P прогона 1
перечитаны вторым дескриптором — 9 из 9 совпали.

## Что здесь НЕ доказано

Присутствие константы доказывает, что она лежит по этому смещению, и — вместе с
цитатой из исходника — делает весьма вероятным, что ссылающийся на неё код
слинкован. Оно **не** доказывает, что этот код исполняется, что игра когда-либо
идёт этим путём, и что значение используется так же, как в исходнике: мёртвая
ветка сохраняет свои константы. Отсутствие не доказывает ничего само по себе —
оно относится к образцу байт, напечатанному в строке, и к поверхности,
напечатанной в `measurement.searched_surface`, и ни к чему шире.

## Команды

Интерпретатор — `D:\Tools\venv-research\Scripts\python.exe`, рабочий каталог —
корень репозитория. Игровой файл и дерево движка открывались только на чтение
(D-01), запись шла только в этот каталог.

```
python tools/static/find_constants.py <MISERY-Win64-Shipping.exe> \
    --ue-source-root "<UE_5.4>/Engine" \
    --out research/evidence/S-08/shipping-constants.json \
    --jsonl-out research/evidence/S-08/constants.jsonl \
    --catalogue-out research/evidence/S-08/catalogue-ue544-cl35576357.json \
    --rows 200

python tools/static/find_constants.py C:/Windows/System32/MSVCP140.dll \
    --ue-source-root "<UE_5.4>/Engine" \
    --catalogue-in research/evidence/S-08/catalogue-ue544-cl35576357.json \
    --out research/evidence/S-08/control-negative-msvcp140.json --rows 0
```
