# STAGE 3 — generic Mod Kit asset/material pipeline

**Verdict: PASS.** Ordinary source assets become MISERY-loadable UE 5.4.4 content
without reproducing the research procedure by hand, and that content loads,
registers and renders in the live game.

**Build:** `misery-24953925-ue5.4.4-bace50f7185d`, UE **5.4.4** CL **35576357**,
branch `++UE5+Release-5.4`. The toolchain is checked before every build and an
unsupported Unreal fails closed.

## What was actually built

Two mods, `alphamod` and `betamod`, from ordinary source files:

| source | kind |
| --- | --- |
| `meshes/shape.glb` | glTF cube, **two primitives → two material slots** |
| `textures/icon.png` | inventory icon |
| `textures/basecolor.png` | base colour map |

Both mods use **the same source filenames**. Everything else — the packed
AO/Roughness/Metallic masks, the flat normal, the constant-colour base — is
generated by the Mod Kit from the spec, and the `.modinfo` note lists
author-supplied and generated files apart.

The synthetic fixture is the **primary** acceptance. The production radio is
regression coverage only: a pipeline proven solely against the asset it was
developed on is not a generic pipeline.

## The live result — 41 checks, 41 passed

`research/instruments/modkit/stage3_acceptance.py`,
evidence `stage3-live-acceptance.json`.

Each of these was read separately, because they can disagree and only
measurement shows it:

1. **Container mounted** — `FPakFile::bIsMounted` true for `Mod_alphamod_P.pak`.
2. **Packages registered** — its `FIoContainerHeader` is non-null. This is a
   *different* fact from (1). The control that makes it meaningful:
   `CT03Probe20260828_P.pak`, a bare `.pak` with no `.utoc` sibling in the same

   `True`.
3. **Objects constructed** — the generated `Texture2D` and `StaticMesh` resolve

4. **Materials** — both slots resolve to distinct `MaterialInstanceConstant`s of
   ours; each parent resolves to the **real vanilla** `M_BasicMaterial`, class

   work was added" means concretely; every texture override resolves to one of
   our own cooked textures, and each slot has its own `BaseColor`.
5. **Two mods at once** — `betamod` mounts and registers while `alphamod` is

   objects, different icon objects, and `betamod`'s slots resolve to *its own*
   materials.
6. **Radio regression** — the production radio still registers through the same

7. **Exact baseline** — after unregistering all three and shutting down:

## The container, read back rather than assumed

`container-reports.json`. Both containers: **10 entries — 9 ExportBundleData
(type 1) + 1 ContainerHeader (type 6)**, and **no type 8 or 9 chunk**.

That is not a formality. The cook itself emits
`ShaderArchive-MISERY-PCD3D_SM5-PCD3D_SM5.ushaderbytecode` (5.5 MB) at the
content root — a shader library named exactly as the game's. A shader library's
chunk id is `CityHash64(lower("<LibraryName>-<Format>"))`, so shipping that would
produce the same chunk id as the game's own, and `FFileIoStore::Resolve` answers
from whichever mounted container it reaches first. Selecting content **by
namespace** excludes it structurally; the histogram proves the exclusion.

The glTF importer also materialises the source file's own embedded materials as
real `UMaterial` assets — which is exactly what compiles new permutations. Those
are pruned before the cook, against the plan's own products.

## Namespace collision, proven twice

Offline, at container level:

| | alphamod | betamod | shared |
| --- | --- | --- | --- |
| container id | `0x930f5e487d152cd3` | `0xe186b916437ad668` | distinct |
| chunk ids | 10 | 10 | **0** |
| package paths | 9 | 9 | **0** |
| asset leaf names | `SM_Shape`, `T_Icon`, … | identical set | — |

The leaf names are identical and nothing collides, because the package path is
derived from the ModId, not from the source filename.

Live, in one process: both containers mounted, both registered simultaneously,
distinct mesh and icon objects, each mod's slots resolving to its own materials.

## Defects found and fixed

1. **The packaging step produced an empty container and exited 0.**
   `-CookedDirectory` pointed at the *content* directory, but the package store
   manifest keys filenames to the *platform* cook root. Every lookup missed,
   each miss was a warning, and the result was a 48-byte `.ucas`. UAT's own
   invocation confirms the platform root. `-PackageStoreManifest` and
   `-ScriptObjects` were also missing.
2. **`.uexp` in the response file.** The zen loader merges a package head and its
   exports into one chunk, so `.uexp` has no package name by design. Listing it
   asked IoStore to resolve something unresolvable. Unknown extensions now fail
   the build closed rather than being skipped silently.
3. Because none of the above changed the exit code, the container is now **read
   back and graded on its contents**. An exit code is not a description of an
   output.
4. **A check that asserted a literal `True`.** The material check originally
   recorded PASS if `verify_live_materials` merely did not raise — it would have
   passed for an empty result. It now asserts on what came back.
5. **A teardown check stricter than the mechanism.** It required the transient
   `DataTable` to be gone from the object array; shutdown *unroots* the table but
   does not run GC. Corrected to the criterion Stage 2 was accepted on
   (`rooted_after == 0`, `owned_count == 0`), with the residual recorded as an
   observation. A later independent read found the object collected, which is
   what "unrooted, awaiting GC" predicts.
6. **Module-global aliasing.** `cr01c5_controller.EXPECT_MATERIALS` is rebound by
   every `bind_item`, so reading it late returned whichever item was bound last —
   a run asked for the radio's 7 slots and got betamod's 2. The radio's literal
   is now captured at import, before the first bind.
7. **The provenance note misstated provenance.** It listed Mod-Kit-generated
   images as author-supplied. Fixed, in the one file whose entire purpose is to
   state provenance correctly.

## Scope honestly stated

* Materials are **not** broadened in this stage. The supported feature set is
  base colour, AO, roughness, metallic and normal, on a vanilla parent. Emissive
  and custom shader graphs are declared **unsupported with an explicit
  diagnostic** — never a silent fallback, and never `WorldGridMaterial`.
* The `_P` container carries no vanilla bytes. Referencing a vanilla material as
  a parent is an *import*; imports ship nothing.
* `global.utoc`/`global.ucas` are produced by the packaging mode but are **never
  staged** — ours would shadow the game's — and their absence from the discovery
  directory is asserted, not assumed.
* The game installation stays read-only. Staging goes to
  `%LOCALAPPDATA%\MISERY\Saved\Paks\`, outside the installation, through
  `runner/containers.apply_profile` and its path guard.
* **Not proven here:** that the fixture *looks* right in the world. Its geometry
  and materials are verified against the live object graph, not with a human eye;
  the radio's visual acceptance was taken separately and is unaffected.
