# RF-01 — разбор незашифрованного `global.ucas`: имена и карта script-объектов

Метод RF-01 (`plan.md` §6.2) отвечает на вопрос, который до сих пор считался требующим
запущенного процесса: **какие reflected-имена есть в сборке и как они связаны между собой.**
Ответ получен офлайн, только чтением, без ключа и без единой записи в память процесса.

Инструмент — `tools/reflection/global_ucas.py` 1.0.0, только стандартная библиотека.
Все раскладки взяты из первоисточника UE 5.4.4 на этой машине (changelist 35576357,
`++UE5+Release-5.4` — тот же changelist, из которого собрана игра), и **каждое поле,
каждая маска и каждая константа несёт ссылку на файл и строку** в docstring модуля.
Ни одно значение не взято по памяти: именно этот класс ошибки уже стоил проекту одного
уверенно неверного ответа (угаданные маски битового поля pak-записи, см. `CK-01`).

Байтов payload здесь нет ни одного. Слой class P содержит только байты заголовков —
структуру, не содержимое, — и ограничен `--literal-samples`.

## Главный результат

**`/Script/MISERY` существует и содержит 29 записей:** 1 пакет, 5 классов (каждый
подтверждён своим CDO), 5 CDO и 18 объектов, принадлежащих классам. Это **первая
поверхность проекта, называющая игровой код**: S-10 нашёл в RTTI Shipping-образа
**ноль** игровых классов.

Всего: **32 797** имён, **34 912** script-объектов, **394** модуля `/Script/`.
Роли: `package` 394, `class_with_cdo` 6506, `class_default_object` 6506,
`member_of_class_with_cdo` 13 396, `package_member_unclassified` 7438,
`cdo_subobject` 672.

**Игровой код шире, чем `/Script/MISERY`.** В staged-списке V-07 четыре `.uplugin` лежат
не под `Engine/Plugins/`, а под `MISERY/Plugins/`, и у каждого есть модуль того же имени
в этом контейнере: `SteamCorePro`, `SIZZ_Menu_Wheel`, `OptimizationTools`,
`UniversalVoiceChatPro`. Один `.uplugin` объявляет несколько по-разному названных
модулей — поэтому сравнение множеств имён «модуль vs плагин» даёт 81 совпадение из 124
и это **не** признак отсутствия остальных; правило записано в самом артефакте
(`staged_plugin_comparison.reading_rule`).

## Почему чтение payload здесь не является расшифровкой (D-02)

Оракулом выступает сам контейнер. `FIoStoreTocEntryMeta::ChunkHash`
(`IoStore.h:89-94`) — это хэш **исходных** данных чанка, «i.e. not the on disk data»
(`IoStore.h:91`), а `FIoHash` есть BLAKE3-160 (`IoHash.h:23, 156-163`). Собранные нами
из `global.ucas` байты хэшируются в
`332cd79f11db0092ef56bc025c032df78b0c3bf8` — ровно то значение, которое TOC хранит для
этого чанка. Значит байты, которые разбирает движок, — это байты, которые прочитали мы,
без шага расшифровки и без шага распаковки между ними. Запас проверки — **160 бит**.

Дополнительно: флаг `ContainerFlags` равен `0x00` (`Encrypted` не выставлен), и все 35
блоков чанка называют метод сжатия с индексом 0, то есть `NAME_None`
(`IoStore.cpp:3258, 2796-2806`). Инструмент читает payload **только** при выполнении всех
трёх условий и не содержит кода расшифровки вообще. Ключ не извлекается, не ищется и не
используется.

## Три проверки тождества, каждая по чужим байтам

Разбор, согласный сам с собой, не доказывает ничего. Каждый слой сверен с данными,
которые лежат в контейнере **отдельно** и записаны **другим** кодом движка:

| Проверка | Что сверяется | Объём | Результат |
|---|---|---|---|
| `chunk_identity` | BLAKE3-160 собранного чанка против `FIoChunkHash` из TOC | 160 бит | совпало |
| `name_hash_verification` | `CityHash64` от каждого имени в нижнем регистре против `uint64`, который batch хранит рядом (`UnrealNames.cpp:4431`) | **32 797** проверок по 64 бита | 0 расхождений |
| `global_index_verification` | `FromScriptPath` (`CityHash64` по UTF-16 от пути в нижнем регистре, `AsyncLoading2.cpp:221-240`) против `GlobalIndex` самой записи | **34 912** проверок по 62 бита | 0 расхождений |
| `cdo_link_verification` | `CDOClassIndex` против правила, которое его породило — **оба** ветвления `PackageStoreOptimizer.cpp:929-943` | 6506 вычисленных + 672 наследованных | 0 расхождений |

Третья проверка — единственное, что вообще способно поймать неверного родителя: она
проверяет **восстановленную цепочку outer**, то есть ту часть, которая превращает список
слов в карту.

**Ветвление `:929` нашлось только потому, что проверка сначала провалилась.** Первая
редакция проверяла лишь ветку «имя начинается с `Default__`» и дала 14 «расхождений» —
все на объектах вида `/Script/Engine/Default__Material/Default__MaterialEditorOnlyData`.
Причина оказалась в коде писателя: `CDOClassIndex = OuterCDOClassIndex` выполняется
**до** проверки префикса, и объект внутри чужого CDO наследует значение outer-а, а не
вычисляет своё. Исправлена причина — модель правила, — а не число.

## Три замощения: разбор покрывает контейнер точно

| Замощение | Результат |
|---|---|
| `toc_tiling` — 9 секций `global.utoc` | покрывают **623 из 623** байт, разрывов 0, перекрытий 0, хвоста 0 |
| `chunk_tiling` — 6 секций внутри чанка | покрывают **2 269 159 из 2 269 159** байт, разрывов 0, перекрытий 0, хвоста 0 |
| `ucas_tiling` — 35 блоков в `global.ucas` | упакованная модель даёт 2 269 159, модель с выравниванием по `FAES::AESBlockSize` — 2 269 168, файл — **2 269 168**: совпадает модель с выравниванием |

Последняя строка объясняет девять «лишних» байт файла: движок читает
`Align(CompressedSize, 16)` байт на блок (`IoStore.cpp:2741`), и упаковщик столько же
резервирует (`IoStore.cpp:1929, 1972`). Инструмент сообщает **обе** модели, а не выбирает
одну молча.

## Две опровергающие пробы: те же факты без раскладки

| Проба | Литеральный скан | Разбор | Итог |
|---|---|---|---|
| `ascii_script_scan` | `/Script/` встречается **394** раза | 394 различных имени пакета | совпало |
| `ascii_default_scan` | `Default__` встречается **6515** раз | 6515 различных имён; их используют **6520** записей | совпало |

Это метод A-08 — `strings` по целому файлу, без единого байта раскладки, — прогнанный
против разбора. Обе цифры A-08 (394 и 6515) воспроизведены.

Разница 6520 против 6515 — не расхождение, а факт о карте: batch хранит каждую **строку**
один раз, и пять имён вида `Default__MaterialEditorOnlyData` используются двумя объектами
в разных пакетах. Первая редакция пробы сравнивала скан с числом **записей** и
рапортовала расхождение там, где его нет; исправлено сравнение, а не число.

## Чего этот контейнер не говорит

Выписано в самом артефакте (`cannot_be_told_from_this_container`) и повторено здесь,
чтобы никто не прочитал в списке больше, чем в нём есть:

* **Чем именно является имя.** В `FScriptObjectEntry` нет тега типа
  (`AsyncLoading2.h:324-337`). `UClass`, `UScriptStruct`, `UEnum` и
  `UDelegateFunction`, лежащие в script-пакете, хранятся одинаково. Единственное
  исключение — связь с CDO (`PackageStoreOptimizer.cpp:932-942`), и именно поэтому в
  словаре ролей есть `class_with_cdo` и нет роли `enum`.
* **Свойства — вообще никогда.** `FProperty` наследует `FField`
  (`UnrealType.h:162`, `Field.h:447`), который не является `UObject`, а карта строится
  `GetObjectsWithOuter` (`PackageStoreOptimizer.cpp:952-957`), который обходит `UObject`-ы.
  Ни одного офсета, размера, типа или порядка свойств в этом контейнере нет и быть не
  может — ни в этой сборке, ни в любой другой.
* **Наследование.** Поля super нет. `OuterIndex` — это владение, не наследование.
* **Непубличные объекты.** `PackageStoreOptimizer.cpp:899-903` пропускает всё без
  `RF_Public`.
* **Используется ли что-либо.** Присутствие означает, что cook видел модуль, а не что
  игра его загружает.
* **Что-либо о `/Game`.** `plan.md` C-11 и §10.5: имя здесь не доказывает существования
  asset-а из `/Game` и ничего не говорит о структуре Blueprint-а.

## Как воспроизвести

```
python tools/reflection/global_ucas.py <install>/MISERY/Content/Paks/global.utoc \
  --staged-plugins research/evidence/V-07/staged-plugins.txt \
  --out research/evidence/RF-01/global-ucas.json \
  --names-out research/evidence/RF-01/global-names.txt \
  --objects-out research/evidence/RF-01/script-objects.tsv \
  --modules-out research/evidence/RF-01/script-modules.tsv \
  --jsonl-dir research/reflection/misery-24826585-ue5.4.4-0eef3715244b \
  --jsonl-scope /Script/MISERY --module /Script/MISERY \
  --build-key sha256:0eef3715244b467c830022c4260a0e2c29c7def1429cb34aa37fdf9b7e14a383 \
  --recorded-at 2026-08-23T00:00:00Z
```

Код возврата 0 означает, что **все одиннадцать** проверок прошли; при любой упавшей
проверке код 2 и вердикт `CHECKS FAILED`. Непроверенный вывод не должен выглядеть как
успешный прогон — поэтому это ошибка, а не предупреждение.

**Оболочка имеет значение.** В Git Bash/MSYS аргумент вида `/Script/MISERY`
переписывается в путь Windows **до** того, как его увидит Python. Первый прогон этой
задачи так и потерял `--jsonl-scope` и записал пять пустых файлов, которые выглядели как
успех. Причина исправлена в инструменте: scope, не выбравший ни одной записи, теперь
отвергается с указанием на переписывание аргумента оболочкой. Команду выше следует
запускать из PowerShell.
