## Что здесь будет

По одному подкаталогу на каждый запуск любого из двух инструментов наблюдения:

```
research/instrument-runs/<timestamp>/
├── manifest.json     ← обязателен, состав ниже
└── <dumps>           ← выгрузки этого запуска
```

Структура пути и наличие манифеста заданы plan.md §9.2 и §19; обязательность манифеста и его
состав — plan.md §8.5.

## Состав `manifest.json` (plan.md §8.5)

Манифест каждого запуска обязан фиксировать:

1. **Уровень инструмента** — ERI или IPP.
2. **`build_key`** сборки, против которой шёл запуск.
3. **Аргументы** запуска.
4. **Версию инструмента.**
5. **Какие возможности были включены** — конкретные `I-*` для ERI и конкретные `P-*` для IPP.
   Для IPP это не формальность: возможности включаются по одной, отдельными явными флагами
   (`--allow-call`, `--allow-mount`, `--allow-spawn`), и манифест — то место, где видно, что было
   включено ровно необходимое.
6. **Состояние `verify_install.py` до и после запуска** (plan.md §1.5, слой 3). Для сессий с IPP
   запуск проверки до и после **обязателен**.

## Почему манифест существует

Не ради отчётности. Три конкретные функции:

* **Воспроизводимость.** Дамп без аргументов, версии инструмента и `build_key` невозможно
  повторить, а невоспроизводимый дамп по plan.md §10.3 не годится в качестве подтверждения.
* **Проверяемость границы «только чтение».** Exit criteria M3 (plan.md §8.6) требуют, чтобы карта
  reflection была получена **без единой записи в память процесса**. Это утверждение о способе,
  и проверить его задним числом можно только по записи о том, что именно было включено.
* **Обнаружение изменений установки.** `verify_install.py` до и после отвечает на вопрос, не
  изменилось ли дерево игры за время сессии — в том числе не по нашей вине (патч Steam,
  сторонний софт).

## Правила, действующие для любого запуска (plan.md §8.5)

* Только полностью контролируемые сессии (решение D-05). Никаких публичных лобби.
* Все дампы — сюда, в `research/`, и **никогда** в папку игры (решение D-01).
* Никакого постоянного присутствия наших файлов в папке игры: ни один инструмент не
  устанавливается «навсегда».
* Вход на уровень 2 (IPP) требует записи об эскалации по plan.md §8.4 — см.
  `research/instruments/ipp/README.md`.

## Схема манифеста — больше не открытый пункт

`tools/kb/validate.py` сопоставляет путь `instrument-runs/*/manifest.json` со схемой
`research/schema/instrument-run-manifest.schema.json`. **Обновлено 2026-08-27: схема написана**
(задача K-02, plan.md §9.4) — до первого запуска, а не после, как и требовалось этим разделом
изначально. Первый появившийся манифест валидируется этой схемой, а не получает предупреждение о
пропущенном слое.

Здесь **не создаётся** файл-пример манифеста: манифест описывает конкретный запуск. Первый
настоящий манифест появится вместе с первым реальным прогоном ERI против живого процесса игры.
